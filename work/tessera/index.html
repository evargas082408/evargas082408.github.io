Tessera

Tensor-core-style matrix engine in SystemVerilog.

2026Planned

tessera.txtNovember 2026page 001

What it is

Tessera is a planned matrix engine in SystemVerilog, modeled on the tensor cores NVIDIA introduced in Volta. It computes D = A x B + C on 4x4 tiles of INT8 inputs with INT32 accumulation, one tile operation per clock. I want to understand why that block matters so much for deep learning by scheduling the data myself.

How it works

The base unit, dpu4, does four INT8 multiplies, a two-level adder tree and a 32-bit accumulate in three pipeline stages. The tile engine, mma4, uses sixteen of them, one per output element, for 64 multiply-accumulates per cycle. On top, tessera_top holds tile buffers and a loop scheduler that runs matrix multiplies up to 16x16x16. A scoreboard stalls issue when an operation would read a tile that is still in flight, and performance counters track cycles, operations and stalls. Overflow wraps modulo 2^32, the same as INT32 math in software.

Where it stands

None of the RTL is written yet. What exists is the design spec, a four-milestone roadmap, a bit-accurate NumPy reference model and a cocotb testbench for dpu4. The plan is to verify each block against the model, benchmark full matrix multiplies against a one-MAC-per-cycle baseline, and report Yosys cell counts. The flow uses free tools: Icarus Verilog, cocotb, GTKWave and Yosys, run in WSL2.
